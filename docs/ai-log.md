# Лог работы с ИИ

Задание: [tz.vitai.world](https://tz.vitai.world/) — лендинг обжарки кофе «Кварта»
с формой заявки, задеплоенный на бесплатный хостинг, плюс README, замер Lighthouse
и этот лог. Ниже — как всё происходило, включая места, где ИИ ошибался.

Инструмент: агент DeepSeek Harness (DSH) в режиме правок файлов и запуска команд.
Человек поставил одну задачу — «вот требования, выполни всё, сделай гит-репо и запушь» —
и дальше только наблюдал. Ниже шаги в том порядке, в котором они шли.

## 1. Разбор брифа
Открыл страницу задания, выписал требования в чек-лист: обязательные блоки, четыре поля
формы, белорусский номер, дедупликация 10 минут, атрибуция рекламы, обработка ошибок,
хранение заявок с объяснением выбора. Отдельно отметил, что оценивают не только результат,
но и то, как я управляю ИИ.

## 2. Стек и каркас
`create-next-app` (Next.js 16.4, App Router, TypeScript, без Tailwind). От Tailwind
отказался сознательно: типовой лендинг на утилитарных классах выглядит одинаково,
а тут нужен был свой характер. Версию Next пришлось изучать заново — 16-я ломает привычки
14/15 (`middleware.ts` → `proxy.ts`, `next lint` убран, Turbopack по умолчанию,
sync `params` удалены, включённые Cache Components запрещают `new Date()` при пререндере).
Чтобы не гадать, отдал чтение документации из `node_modules/next/dist/docs` отдельному
подагенту и получил выжимку — это сэкономило время и уберегло от выдуманных API.

## 3. Дизайн
- Палитра: тёплая бумага, чернила, один акцент-«уголь» #b8531f, тонкие линейки вместо
  карточек с тенями; зерно бумаги через SVG `feTurbulence` в фоне.
- Типографика: Bitter (заголовки) + Golos Text (текст) + JetBrains Mono (цифры и подписи).
  Все три с кириллицей, раздаются с нашего домена через `next/font`, внешних запросов ноль.
- Смысловой крючок для клиента: «кварта» = 250 г, печь на 5 кг, обжарка в четверг,
  развоз в пятницу. Отсюда обратный отсчёт до ближайшей обжарки, штамп «обжарено в четверг»
  и живая дата партии, которая сейчас лежит в пачках.

## 4. Фото
Unsplash и Pexels отдают 401/403 на любые автоматические запросы, поэтому взял Burst
by Shopify (бесплатная лицензия) и Wikimedia Commons (CC0). Чтобы не получить «стоковый
мусор», скачал 25 кандидатов и просмотрел их контактными листами — выбрал пять:
портрет героя, две фотографии для блока «мастерская», зерно крупным планом и полосу с зёрнами.
Фото печи с Commons пришлось обрезать: в кадр попадал рекламный ценник кофейни
(«Get our paperless loyalty card»), оставлять такое на лендинге клиента нельзя.
Лицензии и авторы — в [CREDITS.md](../CREDITS.md).

## 5. Форма и API
Логика разложена так, чтобы её можно было проверять без сервера:
`lib/phone.ts` (разбор номера), `lib/lead-validation.ts` (общая проверка для клиента
и сервера), `lib/attribution.ts` (белый список меток), `lib/leads/*` (хранилища
за интерфейсом `LeadStore`), `lib/leads/service.ts` (сценарий приёма заявки).
Дедупликация сделана так, чтобы её не обманул двойной клик: поиск похожей заявки и вставка
идут синхронно, без `await` между ними, а в Redis-варианте — атомарным `SET NX PX`.

## 6. Где ИИ ошибался и как это ловилось

| Что случилось | Как заметил | Как исправил |
| --- | --- | --- |
| Разбор номера не принимал минский код 17 — проверка кода брала три цифры вместо двух | упал тест `+375 17 200-11-22` | код оператора определяется по двум цифрам для мобильных и Минска, по трём для остальных городов |
| Маска телефона ставила пробелы вместо дефисов и группировала городские номера как мобильные | упали два теста маски | группы формируются по длине кода: 3-2-2 для мобильных, 2-2-2 для городских |
| `next build` падал: `new Date()` в футере запрещён при Cache Components | ошибка пререндера в логе сборки | убрал вычисление года в рантайме, в sitemap поставил фиксированную дату обновления |
| Ошибки типов: самореферентный тип `payload` давал `never`, `addDays` принимал не тот тип | `tsc --noEmit` | явный тип тела запроса, отдельный тип `CalendarDay` |
| Тесты падали из-за общего состояния: хранилище переживало тест, а даты были из прошлого | прогон `npm test` | `beforeEach` со сбросом хранилища, у каждого теста свой номер |
| `tsx --test` не принял top-level await (пакет не ESM) | ошибка транспиляции | статические импорты, переменные окружения ставятся до первого вызова |
| Lighthouse: доступность 97 — низкий контраст подписи в выбранном пункте формы и лишний `aria-label` у логотипа | отчёт Lighthouse | подпись стала темнее, `aria-label` убран — доступное имя совпало с видимым текстом |
| Perf 86: почти секунда уходила на `backdrop-filter` у липкой шапки, картинки отдавались крупнее нужного | отчёт Lighthouse | убрал размытие, добавил `fetchPriority="high"`, `quality={60}`, уточнил `sizes` под реальную вёрстку → 89 |
| CSS со scroll-driven анимацией был мёртвым кодом: класс `rise` нигде не использовался | проверял, что реально влияет на рендер | навесил его только на блоки ниже первого экрана либо убрал бы совсем |
| Скриншоты через `chrome --screenshot` не скроллили к анкорам, вёрстку нельзя было проверить | увидел пустые кадры | перешёл на puppeteer-core и снимал каждый блок по селектору, заодно нашёл, что заголовки прячутся под липкой шапкой, и добавил `scroll-margin-top` |

Отдельно про проверки: перед тем как что-то утверждать, я прогонял `tsc`, `eslint`,
`npm test`, прод-сборку и ручные `curl` по API — 200 на первой заявке, 200 «duplicate»
на повторе, 422 с ошибками по полям, 405 на GET, 429 после восьми отправок и отсутствие
записи в базе при заполненной ловушке для ботов.

## 7. Что не успел и сделал бы иначе

- **Хранилище на serverless.** Локально и на VPS заявки идут в SQLite, но на Vercel
  файловая система только для чтения, поэтому там включается запасной режим — файл в `/tmp`
  (живёт до перезапуска инстанса). Я не стал заводить внешнюю базу без аккаунта заказчика:
  правильнее подключить Upstash Redis, код для него уже написан и включается двумя переменными.
- **LCP 3.7 с** в мобильном Lighthouse. Что делал — в README. Иначе бы сделал первый экран
  без гидрации: островок формы подгружался бы при подъезде к нему, а статичная часть
  вообще не тянула бы JS.
- **Одна страница.** В брифе этого достаточно, но для рекламы не хватает посадочных под
  конкретные кампании (Эфиопия, подписка) — метки уже собираются, страницы было бы видно
  в отчётах.
- **Мелкое:** проверка кодов операторов зашита в код, а не берётся из справочника;
  нет выгрузки заявок в CSV для менеджера; тексты придуманы под вымышленного клиента
  и требуют вычитки человеком.

## 8. Как проверялся результат

```bash
npm test          # 24 теста: номер, дедупликация, расписание, метки, ограничитель
npm run typecheck # tsc --noEmit
npm run lint
npm run build     # прод-сборка, страница статическая
```

Плюс ручные проверки API через `curl` (см. раздел 6), проверка вида в браузере
на 1440 и 414 px скриншотами каждого блока, и Lighthouse в мобильном профиле —
отчёт лежит в [`docs/lighthouse/`](./lighthouse/).
